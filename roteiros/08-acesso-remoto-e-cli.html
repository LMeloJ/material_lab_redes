CLI Cisco, SSH e Administração Remota

Nenhum engenheiro de redes vai ao data center toda vez que precisa alterar uma configuração. O acesso remoto via SSH (porta 22 TCP) permite gerenciar switches e roteadores de qualquer lugar, com criptografia de ponta a ponta.

Neste laboratório você vai dominar os modos de operação do Cisco IOS, configurar interfaces, montar um servidor DHCP, gerar chaves RSA e finalmente acessar o roteador remotamente — tudo pela linha de comando.

Os Modos de Operação do Cisco IOS

O IOS é hierárquico. Cada modo tem um prompt diferente e comandos distintos. Você sobe com comandos de transição e desce com exit ou end.

Prompt Modo Como entrar O que você pode fazer
Router> User EXEC Ao conectar via Console ou SSH ping, traceroute. Não altera configurações.
R-LAB# Privileged EXEC enable Todos os show, debug, write memory, recarregar.
R-LAB(config)# Global Config configure terminal Hostname, usuários, DHCP, SSH, domínio, rotas.
R-LAB(config-if)# Interface Config interface gigabitethernet 0/0/0 IP, máscara, encapsulamento, no shutdown.
R-LAB(config-line)# Line Config line vty 0 4 transport input ssh, login local.
R-LAB(config-dhcp)# DHCP Pool ip dhcp pool NOME network, default-router, dns-server, lease.

Navegação entre modos — reproduza no Packet Tracer:

Router>              ← User EXEC
Router> enable
Router#              ← Privileged EXEC
Router# configure terminal
Router(config)#     ← Global Config
Router(config)# interface gigabitethernet 0/0/0
Router(config-if)#  ← Interface Config
Router(config-if)# exit   ← volta um nível
Router(config)# end    ← vai direto ao Privileged
Router#
⚠️ Atalhos: en = enable, conf t = configure terminal, int gi0/0/0 = interface gigabitethernet 0/0/0. Use ? para ver comandos disponíveis no modo atual.

Experimento 1: Acesso por Console e Configuração de IPs

Primeiro acesso ao roteador — sempre pelo cabo Console, nunca pela rede.

Por que Console primeiro? O roteador sai de fábrica sem IP configurado. Sem IP não tem SSH. O cabo Console é a conexão out-of-band que não depende da rede.

💻 Passo 1 — Abrir o Terminal via Console

  1. a)Clique no PC conectado ao console do R-LAB → aba Desktop → Terminal.
  2. b)Clique em OK. Se aparecer "Would you like to enter the initial configuration dialog?" → responda no.
  3. c)Você verá: Router> — modo User EXEC.

🏷️ Passo 2 — Enable e Hostname

Router> enable
Router# configure terminal
Router(config)# hostname R-LAB
R-LAB(config)#   ← prompt muda imediatamente!
Por que o hostname importa? O IOS usa o hostname para compor o nome da chave RSA (R-LAB.labredes.local). Sem hostname personalizado, o crypto key generate rsa vai falhar.

🔌 Passo 3 — Configurar Interface Gi0/0/0 (Clientes) 

R-LAB(config)# interface gigabitethernet 0/0/0
R-LAB(config-if)# ip address 192.168.1.1 255.255.255.0
R-LAB(config-if)# no shutdown
! Saída: %LINK-5-CHANGED: Interface GigabitEthernet0/0/0, changed state to up
R-LAB(config-if)# exit
Por que no shutdown? Por padrão, interfaces Cisco vêm administrativamente desligadas. O no shutdown as ativa.
✓ Verificação: do show ip interface brief. Gi0/0/0 deve aparecer up/up.
🤔Reflexão — Pense antes de continuar

Você configurou um IP na Gi0/0/0. Neste momento, o PC-A conseguiria fazer ping 192.168.1.1? E o que ainda falta para ele receber um IP automaticamente?

Experimento 2: Servidor DHCP no Roteador

O roteador distribui IPs para os clientes automaticamente.

Como funciona? Primeiro excluímos endereços estáticos (para evitar conflito), depois criamos um pool com a faixa, o gateway e o DNS.

📦 Configurar o Pool DHCP 

! Exclui endereços estáticos do pool (não serão distribuídos)
R-LAB(config)# ip dhcp excluded-address 192.168.1.1 192.168.1.10

! Cria o pool de endereços DHCP
R-LAB(config)# ip dhcp pool POOL_CLIENTES
R-LAB(config-dhcp)# network 192.168.1.0 255.255.255.0
R-LAB(config-dhcp)# default-router 192.168.1.1
R-LAB(config-dhcp)# dns-server 8.8.8.8
R-LAB(config-dhcp)# exit
excluded-address

Reserva .1 a .10. Clientes recebem .11 em diante.

network

Define a rede do pool.

default-router

Informa o gateway ao cliente no DHCP Offer.

! Configure DHCP no PC-A (Desktop > IP Config > DHCP), depois verifique:
R-LAB# show ip dhcp binding
IP address       Hardware Addr         Type
192.168.1.11     00D0.97A8.XXXX        Automatic

Conceito Chave: O que são Linhas VTY? (Console Física vs Terminal Virtual)

No Cisco IOS, o termo "line" refere-se a portas de entrada para sessões de terminal de comando (CLI). Existem dois tipos fundamentais que você precisa diferenciar:

🔌 Console Física (line con 0) Porta Física
  • • Porta serial física RJ-45 azul no chassi do equipamento.
  • • Usada para a instalação inicial ou quando a rede IP está fora do ar.
  • • Não usa endereço IP nem depende de interfaces de rede ativas.
  • • Permite apenas 1 única conexão física simultânea (linha 0).
🌐 Terminal Virtual (line vty 0 4) Porta Lógica (Rede)
  • • VTY = Virtual TeleTYpewriter (terminais virtuais em memória).
  • • Usada para gerenciamento remoto via rede (SSH / Telnet).
  • • Depende de interface de rede com IP configurado e pilha TCP/IP ativa.
  • • Os números 0 4 indicam 5 sessões simultâneas (0, 1, 2, 3 e 4). Em switches Cisco geralmente são 16 (0 15).
transport input ssh: Bloqueia Telnet (porta 23 em texto claro) e força uso exclusivo do SSH criptografado (porta 22) nas VTYs.
login local: Ordena ao roteador que autentique quem conecta usando a tabela interna de usuários (username admin secret ...) em vez de uma senha genérica de linha.

📤 Telnet — Texto Claro (EVITE!)

USER: admin
PASS: cisco123

Qualquer um com Wireshark lê suas credenciais em claro.

🔐 SSH — Criptografado (CORRETO)

7b 4a 9c 1e f3 08 42 aa 91 2b cc 87 ...

Indecifráveis sem a chave privada do roteador.

🤔Reflexão

Por que o tamanho da chave RSA importa? O que acontece com 512 bits vs 2048 bits?

O transport input ssh bloqueia Telnet nas VTYs. A porta Console também fica protegida pelo SSH?

Experimento 5: Gerenciamento Seguro de Switch L2 (SVI & SSH)

Aprenda passo a passo a configurar a interface virtual SVI, o gateway padrão e o SSH nas 16 linhas VTY do switch corporativo.

🧠

Fundamento Teórico 1: Se o Switch é de Camada 2, por que ele precisa de IP?

Um switch tradicional de acesso (como o Cisco Catalyst 2960) opera na Camada 2 (Enlace): ele lê cabeçalhos Ethernet, armazena endereços MAC em sua tabela CAM e comuta quadros em alta velocidade entre suas portas físicas. Para que os computadores conversem entre si ou acessem a internet, o switch não precisa de nenhum endereço IP. Ele é totalmente transparente aos dados dos usuários.

A chave para entender isso é a distinção entre os dois planos de operação de um equipamento de rede:

🚀 Plano de Dados (Data Plane) Sem IP

Tráfego que atravessa o switch: computadores conversando entre si ou trafegando rumo ao roteador.

Origem: PC-Admin (10.0.0.11) → Destino: R-LAB (10.0.0.1)
Ação do Switch: Comuta o quadro Ethernet diretamente via circuito ASIC de hardware, sem envolver a CPU nem olhar endereços IP.
🔐 Plano de Gerenciamento (Management Plane) Exige IP

Tráfego cujo destino é o próprio switch: quando a equipe de redes precisa administrar o equipamento remotamente via SSH, SNMP ou Syslog.

Origem: PC-Admin → Destino: SW-Admin (10.0.0.2)
Ação do Switch: A CPU do switch precisa ter uma pilha TCP/IP ativa para escutar na porta 22 (SSH) e autenticar a sessão.
1

O que é a SVI (Switch Virtual Interface)?

Em um roteador, cada porta física é uma interface de Camada 3 independente que aceita o comando ip address. Já em um switch L2, as portas físicas (FastEthernet 0/1 a 0/24) são puramente de Camada 2 — se você tentar digitar ip address nelas, o IOS retornará erro:

SW-Admin(config-if)# ip address 10.0.0.2 255.255.255.0
% Invalid input detected at '^' marker.

Para resolver isso, o Cisco IOS cria uma interface lógica interna conectada diretamente à CPU: a SVI (Switch Virtual Interface), por padrão a interface vlan 1. É ela que recebe o IP de gerenciamento.

2

Por que o comando ip default-gateway é obrigatório?

Um switch L2 não possui tabela de rotas (ele não roteia pacotes). Se a requisição SSH vier de uma máquina na mesma sub-rede (PC-Admin em 10.0.0.11), o switch responde diretamente.

Mas e se a conexão vier do PC-A (192.168.1.x) ou de uma VPN? O pacote chega ao switch através do roteador R-LAB. Porém, ao gerar a resposta de volta para 192.168.1.x, o switch não sabe o que fazer com aquele IP externo.

Sem Gateway: O switch descarta o pacote de retorno e a sessão SSH sofre timeout.
Com Gateway (ip default-gateway 10.0.0.1): O switch envia os pacotes de volta para a interface do R-LAB, completando o handshake TCP com sucesso!
1

Passo 1: Acesso Inicial à CLI do Switch

No Cisco Packet Tracer, clique diretamente no dispositivo SW-Admin e selecione a aba CLI (ou ligue o cabo Console do PC-Admin à porta Console do switch e abra o aplicativo Terminal).

Pressione ENTER para receber o prompt inicial no modo User EXEC: Switch>.

Passo 2: Hostname e Senha do Modo Privilegiado

Mudar o nome do switch é pré-requisito obrigatório para gerar chaves RSA. Além disso, protegemos o modo privilegiado com uma senha segura (class): 

Switch> enable
Switch# configure terminal
! Define o nome do switch (essencial para a chave RSA)
Switch(config)# hostname SW-Admin
! Protege o modo privilegiado com hash criptografico
SW-Admin(config)# enable secret class
3

Passo 3: Configuração da SVI (Interface VLAN 1) e Default Gateway

Agora atribua o IP 10.0.0.2/24 à interface virtual vlan 1, ative-a com no shutdown e informe o IP do roteador R-LAB como gateway padrão: 

! 1. Entra no modo de configuracao da interface virtual SVI
SW-Admin(config)# interface vlan 1
! 2. Atribui o IP de gerenciamento na mesma rede do PC-Admin
SW-Admin(config-if)# ip address 10.0.0.2 255.255.255.0
! 3. Ativa a interface administrativa (por padrao ela vem em shutdown)
SW-Admin(config-if)# no shutdown
SW-Admin(config-if)# exit
! 4. Aponta o roteador R-LAB como gateway para alcancar outras redes
SW-Admin(config)# ip default-gateway 10.0.0.1
Comando Significado / Efeito Importância
interface vlan 1 Entra na SVI nativa do switch Cria o ponto de presença IP da CPU do switch
no shutdown Altera o estado para UP Sem este comando a SVI permanece inativa
ip default-gateway 10.0.0.1 Define o salto de saída para outras sub-redes Permite que o switch responda a conexões do PC-A e filiais

Passo 4: Habilitação de SSHv2 e Endurecimento das 16 Linhas VTY

Agora geramos o par de chaves RSA de 1024 bits e configuramos as 16 linhas VTY (0 a 15) para aceitar apenas SSH autenticado com a conta local: 

! 1. Dominio IP corporativo (necessario para compor a chave RSA)
SW-Admin(config)# ip domain-name labredes.local

! 2. Gera as chaves criptograficas RSA (digite 1024 no prompt)
SW-Admin(config)# crypto key generate rsa
How many bits in the modulus [512]: 1024
% Generating 1024 bit RSA keys, keys will be non-exportable...[OK]

! 3. Forca a versao 2 do protocolo SSH
SW-Admin(config)# ip ssh version 2

! 4. Cria conta de administrador com privilegio maximo (15)
SW-Admin(config)# username admin privilege 15 secret cisco123

! 5. Endurece TODAS as 16 linhas virtuais (0 a 15)
SW-Admin(config)# line vty 0 15
SW-Admin(config-line)# transport input ssh
SW-Admin(config-line)# login local
SW-Admin(config-line)# exit
SW-Admin(config)# end

! 6. Salva permanentemente as configuracoes na NVRAM
SW-Admin# copy running-config startup-config
Destination filename [startup-config]? [ENTER]
Building configuration...[OK]
💡 Diferença Roteador vs Switch: No roteador ISR 4331 utilizamos line vty 0 4 (5 linhas virtuais). No switch Cisco 2960 utilizamos line vty 0 15 (16 linhas virtuais). Se você configurasse apenas 0 4 no switch, as linhas 5 a 15 continuariam sem segurança!

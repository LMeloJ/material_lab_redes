Modelos Mentais: Do Isolamento L2 ao Roteamento L3 & Internet

⚡

O Comando 'ip routing'

No Cisco Catalyst 3560/3650, o switch nasce operando apenas em Camada 2. O comando global ip routing é a chave que liga a tabela de rotas e o motor de comutação L3 por hardware (CEF).

🚪

SVI (Switch Virtual Interface)

interface Vlan 10 cria uma porta lógica no Core que atua como o Default Gateway (ex: 192.168.10.1) para todas as máquinas daquela VLAN nos andares.

📡

ip helper-address (DHCP Relay)

Como broadcasts DHCP não cruzam roteadores, o switch core intercepta o Discover na SVI e o reencaminha como Unicast direto para o servidor SRV-NET na DMZ (192.168.30.40).

🌐

NAT Overload (PAT) na Borda

O roteador R-EDGE traduz todos os IPs privados das VLANs (192.168.x.x) para o único IP público da WAN da operadora através de portas TCP/UDP dinâmicas.

Guia de Comandos Cisco IOS: Roteamento Core e NAT

1. Ativação do Roteamento L3 e Criação das SVIs no SW-CORE-MDF

No Switch Core 3560, ligamos o motor de roteamento e configuramos cada SVI com seu IP de gateway e o helper-address: 

enable
configure terminal
hostname SW-CORE-MDF

! 1. Ligar o Roteamento L3 por Hardware
ip routing

! 2. Gateway da VLAN 10 (ADM) com DHCP Relay para a DMZ
interface Vlan10
 description GATEWAY-ADM
 ip address 192.168.10.1 255.255.255.0
 ip helper-address 192.168.30.40
 no shutdown
exit

! 3. Gateway da VLAN 20 (VOIP)
interface Vlan20
 description GATEWAY-VOIP
 ip address 192.168.20.1 255.255.255.0
 ip helper-address 192.168.30.40
 no shutdown
exit

! 4. Gateway da VLAN 30 (DMZ Servidores)
interface Vlan30
 description GATEWAY-DMZ-DATACENTER
 ip address 192.168.30.1 255.255.255.0
 no shutdown
exit

! 5. Gateway da VLAN 40 (GUEST Wi-Fi)
interface Vlan40
 description GATEWAY-GUEST
 ip address 192.168.40.1 255.255.255.0
 ip helper-address 192.168.30.40
 no shutdown
exit

! 6. Rota Padrão Estática apontando para o Roteador de Borda R-EDGE
ip route 0.0.0.0 0.0.0.0 10.0.0.2

2. Configuração de NAT/PAT Overload no Roteador de Borda R-EDGE

No roteador de borda conectado à operadora, configuramos a tradução de todos os blocos internos para o IP da interface WAN: 

enable
configure terminal
hostname R-EDGE

! Interface Interna (voltada para o SW-CORE-MDF)
interface GigabitEthernet0/0
 ip address 10.0.0.2 255.255.255.252
 ip nat inside
 no shutdown
exit

! Interface Externa (WAN conectada à Nuvem/ISP)
interface GigabitEthernet0/1
 ip address 200.19.1.2 255.255.255.252
 ip nat outside
 no shutdown
exit

! ACL permitindo a tradução de todas as redes corporativas
access-list 1 permit 192.168.0.0 0.0.255.255

! Ativação do NAT Overload (PAT) na interface de saída WAN
ip nat inside source list 1 interface GigabitEthernet0/1 overload

! Rota de volta para o Core das sub-redes internas
ip route 192.168.0.0 255.255.0.0 10.0.0.1

! Rota padrão para a Internet da operadora
ip route 0.0.0.0 0.0.0.0 200.19.1.1

Armadilhas Comuns no Roteamento e NAT

❌ Esquecer o 'ip routing'

Switch L3 não Roteia

Se você criar todas as SVIs mas esquecer de digitar ip routing no modo de configuração global, os hosts pingarão seu próprio gateway mas NUNCA alcançarão nenhuma outra VLAN ou servidor.

⚠️ Helper-Address Faltante

PC preso em 169.254.x.x (APIPA)

Se o PC de um andar não receber IP do SRV-NET, certifique-se de que a SVI daquela VLAN possui ip helper-address 192.168.30.40 apontado para o IP exato do servidor DHCP na DMZ.

🌐 Rota Reversa no R-EDGE

Esquecer rota interna no NAT

O roteador de borda sabe entregar pacotes na Internet, mas precisa de uma rota estática ip route 192.168.0.0 255.255.0.0 10.0.0.1 para saber onde devolver os pacotes quando chegam ao switch Core.

Laboratório 04 • Comutação L2 & Roteamento L3

Como o Switch Aprende e Como o Roteador Encontra o Próximo Salto

Um switch opera na Camada 2 inspecionando o MAC de Origem para preencher sua memória CAM (Content-Addressable Memory). Já um roteador opera na Camada 3 consultando sua Tabela de Roteamento e decrementando o campo TTL (Time To Live) a cada salto para evitar loops infinitos.

Comando CAM: show mac address-table
Link WAN Ponto a Ponto: 10.0.0.0/30 (Máscara .252)
Comando Rota: ip route <dest> <mask> <next-hop>
1

Modelos Mentais: Tabela CAM vs Tabela de Rotas

📬

O Carteiro Observador

"Aprendizado por Source MAC"

O switch nunca pergunta "quem é você?". Ele simplesmente olha o remetente de qualquer carta recebida na porta Fa0/1 e anota no caderninho: "Porta 1 = MAC A".

📢

O Grito no Pátio

"Unknown Unicast Flooding"

Se o switch precisa entregar um quadro para o MAC B e nunca ouviu falar dele, ele replica o pacote para absolutamente todas as portas ativas exceto a de entrada.

🛣️

A Placa de Estrada

"Next-Hop (Próximo Salto)"

O roteador R1 não sabe como é o bairro final na LAN B; ele apenas sabe a regra: "Quer ir para a rede 192.168.2.0? Entregue para o IP do Roteador R2 (10.0.0.2)".

⏳

A Ampulheta do Pacote

"TTL Decrement (Time to Live)"

A cada roteador atravessado, o cabeçalho IP perde 1 no TTL. Se chegar a 0, o roteador descarta o pacote e manda de volta um ICMP Time Exceeded ao remetente.

Guia de Comandos Cisco IOS

🔀 1. Inspeção e Limpeza da Tabela CAM no Switch 

enable
! Visualizar a tabela de endereços MAC completa
show mac address-table

! Limpar todas as entradas dinâmicas para forçar flooding de aprendizado
clear mac address-table dynamic

! Inspecionar porta específica
show mac address-table interface fastEthernet 0/1

🧭 2. Configuração de Rotas Estáticas Bidirecionais

// Configuração Roteador R1
enable
configure terminal
hostname R1

! Link LAN A
interface gigabitEthernet 0/0
 ip address 192.168.1.254 255.255.255.0
 no shutdown
exit

! Link WAN /30 com R2
interface gigabitEthernet 0/1
 ip address 10.0.0.1 255.255.255.252
 no shutdown
exit

! Rota Estática para LAN B via R2
ip route 192.168.2.0 255.255.255.0 10.0.0.2

do show ip route
// Configuração Roteador R2
enable
configure terminal
hostname R2

! Link LAN B
interface gigabitEthernet 0/0
 ip address 192.168.2.254 255.255.255.0
 no shutdown
exit

! Link WAN /30 com R1
interface gigabitEthernet 0/1
 ip address 10.0.0.2 255.255.255.252
 no shutdown
exit

! Rota Estática para LAN A via R1
ip route 192.168.1.0 255.255.255.0 10.0.0.1

do show ip route

Armadilhas Comuns de Roteamento & CAM

⚠️ 1. A Rota de Ida Existe, a de Volta Não!

O erro mais clássico dos alunos: configurar a rota em R1 e esquecer de R2. O pacote chega perfeitamente ao host de destino, mas na hora de responder, R2 não tem rota para a LAN A e descarta o Echo Reply!

Sintoma: Request timed out mesmo com as interfaces ligadas.
⚠️ 2. Máscara WAN /30 Inválida

A máscara 255.255.255.252 (/30) possui apenas 2 endereços úteis: .1 e .2. Usar .3 (broadcast) ou .0 (rede) causará erro de sobreposição (overlap).

Regra: Em links /30, configure estritamente IP ímpar em uma ponta e par na outra.
⚠️ 3. Apontar Next-Hop para Interface Local

Digitar em R1: ip route 192.168.2.0 255.255.255.0 10.0.0.1 (o IP do próprio R1!). O next-hop deve ser SEMPRE o IP da interface do vizinho do outro lado do cabo (10.0.0.2).

Next-hop = Endereço do Roteador Vizinho.
